## 第二部分：第二题

第二题没有代码实现，并且相对比较复杂，就简单描述下自己的想法：

1. **电站数据api调用次数限制**：需要在有限次数内将数据取出。
2. **数据量的考虑**
   ：根据文档和统计的要求，发电量的最小时间单位是小时，因此传统数据库就可以。数据库的表大致应该有以下几张表（电站表、设备表、小时发电量表、日发电量表、年发电量表)
   ，发电量表都需要有一个类型字段（电站、设备表），即使考虑历年数据量累计较大，也可以考虑分表（以电站、设备为key,进行取模分表）。
    - 根据限流次数要求，计算出每天可以统计多少次(n)，进行定时更新（更新结果不入库，而是临时缓存），但是要留下至少2次调用，在刚过了凌晨后今天前一天电站、设备数据最后更新后入库。
    - 如果考虑查询性能，可以对历年、月数据进行缓存、最近的时间的小时数据进行短时间缓存，当天查询的历时数据进行短时间缓存，以提高缓存命中率。
    - 另外还应该考虑数据同步服务可能会出现问题：如果掉线而导致某天数据没有同步的问题，可以设计一张同步结果表，以方便服务上线后自动同步
